# Code of Conduct

## The short version

Be decent. Assume the other person is trying to help. Argue about the code, not
about the person writing it.

## What is expected

- Give feedback on the work: what is wrong, why, and what would be better.
- Accept feedback the same way. A rejected patch is not a rejected person.
- Say plainly when you do not know something. Guessing confidently wastes
  everyone's time.
- Respect that maintainers volunteer their attention, and that a "no" to a
  feature is a legitimate answer.

## What is not

- Harassment, insults, or personal attacks — in issues, PRs, commits, or private
  messages tied to this project.
- Sexualized language or imagery, and unwelcome attention of any kind.
- Publishing anyone's private information without their explicit permission.
- Deliberately derailing discussions, or persistent bad-faith argument after a
  decision has been made and explained.

## Scope

This applies in every project space — issues, pull requests, discussions, commit
messages, and any channel where you are representing the project.

## Enforcement

Report through the contacts on [sshlg.me](https://sshlg.me), or privately via
[GitHub Security Advisories](https://github.com/ssheleg/sshlg-skills/security/advisories/new)
if the report itself is sensitive. Reports are handled privately; reporter
identity is not shared with the reported person.

Maintainers may edit or remove contributions, or block accounts, when this
document is not followed. Responses scale with what happened: a correction for a
first lapse, removal of the content for a repeated one, a block for harassment or
bad faith.
