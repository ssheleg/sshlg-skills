**G2 is retracted, and the retraction belongs in the record.** It was written up as
med-high impact — "the family's front door is the one repo the channel cannot see" — on the
strength of the 404 plus a guess at its cause. Checked properly afterwards, from the
umbrella's own directory rather than from a submodule the shell had been left in:

```
git ls-files | grep -c SKILL.md   ->  0
ls .claude-plugin                 ->  (none)
git ls-tree HEAD -- skills        ->  one tree of gitlinks
```

The umbrella tracks **no skills at all**. `skills.sh` indexes repositories you install
*skills* from, and the umbrella is a **launcher** — its install path is
`npx sshlg-skills install`, never `npx skills add ssheleg/sshlg-skills`. A listing would
advertise an install path that does not exist, so the 404 is the channel being right.
Nothing to fix, and the row is kept rather than deleted because the mistake is instructive:
the 404 was real, the cause was real, and the *conclusion* was still wrong. This audit
recorded four instrument defects on the site's own history; this is the fifth of the class
and the first belonging to the plan rather than to a probe.

**G3 is where the honest answer differs from the intuitive one.** All ten repositories
already carry a full description, a homepage, 8 topics and a custom OG image. The
comparison that settles it: `mattpocock/skills` has **237,955 stars and 20,248 forks with

audience, and placement in Claude Code's **official** marketplace, where installation is
`claude plugins install <name>` with nothing to add first. Pursuing that placement is the
highest-leverage item on this page and it is not an SEO change; it is a submission.

**What NOT to do about G3**, recorded because it is the tempting move: adding more topics,
more keywords, or repeating the target phrases through the READMEs. The counter-example
ranks at the top with none of it, and the myth list this skill ships refuses keyword
density as a lever. It would cost ten commits and change nothing measurable.

## The star-history widget — blocked upstream, and the block is real

Requested during this pass. **Not shipped, and shipping it today would have been wrong.**
`api.star-history.com` currently returns a placeholder image reading *"GitHub restricted
access to star data"* for every repository including our own — verified 2026-08-27 by
fetching the endpoint for `ssheleg/sshlg-skills`, single-repo and multi-repo forms, all
60 KB and all the same placeholder. GitHub restricted the stargazers endpoint on
2026-06-30 to a repository's own admins and collaborators.

The vendor's workaround requires generating a GitHub token, handing it to
`star-history.com`, and embedding an **encrypted token** in the public README. That is a
decision about giving a third party a credential over ten repositories, which is the
operator's to make and not an agent's to take. Until it is made, embedding the widget
would put a broken chart-shaped image at the top of ten READMEs, which reads as an
unmaintained project — worse than the absence it replaces.

## What this plan cannot claim

The site has never been crawled, so **no finding here is known to have changed what any
engine does** — only what the pages offer one. That was true of the 2026-08-26 plan as
well, and it stated it; the difference is that the reason is now measured rather than
assumed, and the cause has been removed. PSI quota was exhausted, so nothing about field
performance is claimed. GitHub's ranking model is not public, so Track C reports observed
rank and refuses to name a mechanism.
