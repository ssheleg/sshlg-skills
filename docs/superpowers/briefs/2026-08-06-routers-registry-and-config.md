## Решения интейка

| # | Решение |
|---|---|
| D-01 | **task-pipeline владеет циклом целиком.** Граница остаётся «меняет репозиторий», планирование внутри неё названо явно (стадии 2–4 — это и есть брейншторм/спека/план). Конкурирующая секция «Task planning — Superpowers cycle» удаляется из глобальных инструкций |
| D-02 | **Роутер — самостоятельная единица**, а не свойство участника. Реестр по имени, у каждого `requires: [участники]`, возможно пустой |
| D-03 | **Граница sheleg-design против super-ux — по фиделити.** super-ux: что на экране и в каком порядке (флоу, экраны, состояния, сценарии). sheleg-design: как это выглядит и движется (токены, темы, типографика, мотион, визуальный язык бренда, граница с Figma) |
| D-04 | **`evidence-docs` — обе половины:** каждое утверждение несёт чек (`file:line`, команда+вывод, имя теста; число вычислено, не пересказано) И «доки в синхроне» — команда с кодом выхода, доки едут тем же изменением |
| D-05 | **`seo-llmo` — правило проектирования, не отправка в аудит.** Публичная веб-поверхность проектируется для человека и для машины, которая её процитирует. `seo-aeo-audit` назван в том же тексте как проверка постфактум |
| D-06 | **Восемь роутеров.** Шесть от участников + два правила без участника. `make-skill` и `agent-sync` получают узкие границы |
| D-07 | **Настройка крутит роутеры по имени: on/off.** `~/.sshlg-skills/config.json` рядом с `state.json`. Стадии пайплайна не трогаем — ими владеет `pipeline.json` в проекте |
| D-08 | **`off` удаляет секцию и сохраняет её тело** в `config.json`. `on` восстанавливает ровно сохранённое — иначе тумблер туда-обратно стирает рукописные формулировки, которые перенесла миграция |
| D-09 | **UI-вердикт: да, но цепочка отложена.** Записанный вейвер. Взамен каждая команда `config` получает REQ-строку с точным ожидаемым выводом и кодом выхода |
| D-10 | **Область — глобальная.** Основание не мнение: спека `2026-08-05-global-routing-block-design.md:135` — per-project правила вне области, ими владеет `/ux-rule` |
