# Design — реестр роутеров и настройки пака

Дата: 2026-08-06 · Статус: утверждено (интейк подтверждён оператором) · Бриф:
`briefs/2026-08-06-routers-registry-and-config.md`

## Проблема

Три роутера жили в двух файлах: тексты в `lib/router-texts.js` (`BY_MEMBER`),
строки таблицы в `lib/routers.js:134` (`ROUTER_ROWS`). Ничто не сравнивает
половины между собой — роутер может существовать в одной и отсутствовать в
другой, и оба файла останутся синтаксически безупречны. При трёх роутерах это
терпимо; при восьми это заведённая ошибка.

Второе: роутер сегодня — **свойство участника**. Правило, за которым не стоит
скил («документация с доказательствами», «SEO/LLMO при проектировании»), в этой
модели не имеет места жительства.

Третье: включить или выключить отдельное правило нельзя. Единственный тумблер —
метка `OPTOUT`, и она выключает всё сразу.

## Заперто на стадии 1 (не по памяти)

`fs.writeFileSync(file, data, {mode})` передаёт `mode` **только в `open()`**;
на существующем файле `open()` с `O_CREAT` его игнорирует, и `chmod`/`fchmod`
не вызывается никогда. Плюс маска процесса. Источник: `nodejs/node`,
`doc/api/fs.md` + `lib/internal/fs/promises.js` (получено через context7,
2026-08-06).

**Следствие, обязательное к исполнению:** режим 0600 достигается только явным
`fs.chmodSync` после записи. Это уже сделано в `lib/consent.js:37-41`. Конфиг
обязан идти тем же путём, а не заводить вторую реализацию.

## Контракты

### `lib/routers-registry.js` (новый) — единственный дом роутера

```js
/**
 * name -> { requires, answers, when, text }
 * Порядок ключей объекта — порядок строк в таблице. Одно место, один порядок.
 */
const REGISTRY = {
  'task-pipeline': { requires: ['task-pipeline'], answers: '…', when: '…', text: '…' },
  'super-ux':      { requires: ['super-ux'],      answers: '…', when: '…', text: '…' },
  'sheleg-design': { requires: ['sheleg-design'], answers: '…', when: '…', text: '…' },
  'copywriting':   { requires: ['super-ux'],      answers: '…', when: '…', text: '…' },
  'seo-llmo':      { requires: [],                answers: '…', when: '…', text: '…' },
  'evidence-docs': { requires: [],                answers: '…', when: '…', text: '…' },
  'make-skill':    { requires: ['make-skill'],    answers: '…', when: '…', text: '…' },
  'agent-sync':    { requires: ['agent-sync'],    answers: '…', when: '…', text: '…' },
};

/** Имена в порядке реестра. */
function order(): string[]

/** Строки таблицы для присутствующих имён, в порядке реестра. */
function rows(names: string[]): Array<[name, answers, when]>

/**
 * Роутеры, которые ДОЛЖНЫ быть в блоке: requires ⊆ installed И не выключены.
 * Возвращает { name: text }.
 */
function resolve(opts: { installed: string[], config?: Config }): Record<string,string>

/**
 * Роутеры, которые должны быть УДАЛЕНЫ из блока: известны реестру,
 * но выключены конфигом. Участник не установлен — это не «выключен»:
 * секции и так нет, удалять нечего.
 */
function disabled(opts: { installed: string[], config?: Config }): string[]
```

`lib/routers.js` перестаёт владеть `ROUTER_ROWS` и берёт порядок и строки
отсюда. `lib/router-texts.js` остаётся как **тонкий фасад** (`SUPER_UX`,
`COPYWRITING`, `TASK_PIPELINE`, `BY_MEMBER`, `forMembers`) — его импортирует
`bin/` и существующий набор тестов; ломать этот контракт незачем.

### `lib/store.js` (новый) — примитивы файла состояния

```js
function readJson(file): object      // любой сбой -> {}; сбой не есть согласие
function writeJson(file, patch): object  // merge, writeFileSync + chmodSync(0o600)
```

`lib/consent.js` переписывается на них **без изменения своего публичного API**
(`statePath`, `readState`, `writeState`, `askConsent`). Доказательство
безопасности рефакторинга — `consent_test.js` проходит без единой правки.

### `lib/config.js` (новый)

```js
function configPath(home): string     // <home>/.sshlg-skills/config.json

/**
 * { routers: { <name>: 'off' }, stash: { <name>: '<тело секции>' } }

```

### `lib/routers.js` — изменения

`upsert(text, routers, opts)` получает третий аргумент:

```js
opts = { remove: string[] }   // имена секций, которые должны исчезнуть
```

Правила удаления, каждое — защита конкретного байта:

1. Удаляется сегмент секции и **ровно один** соседний chrome-сегмент, если его
   `raw` **точно равен** `'\n\n'` или `'\n'`. Chrome с любым другим содержимым
   не трогается никогда — там живут заголовок, таблица и всё, что написала
   рука.
2. Таблица перегенерируется из выживших секций — механика уже есть
   (`routers.js:219`), удаление получает исчезновение строки бесплатно.
3. Секция, которой нет, — не ошибка: `remove` идемпотентен.
4. `before` и `after` в рендере не участвуют — запись вне сентинелов
   невозможна по построению, и удаление этого не меняет.

### `lib/migrate.js` — вытесненные заголовки

```js
const SUPERSEDED = [
  { id: 'task-planning', match: /^##[ \t]+Task planning(?=[\s—-]|$).*$/m,
    supersededBy: 'task-pipeline' },
];
```

Заголовок удаляется из файла **только когда роутер `supersededBy` реально
записывается** — вытеснение без замены было бы просто удалением чужого текста.
Тело уезжает в `config.stash['superseded:task-planning']`, а не в никуда:
глобальный `CLAUDE.md` не под гитом, откатывать нечем.

`\b` запрещён и здесь: граница слова в JavaScript — ASCII-only, и на кириллице
не срабатывает (`migrate.js:18-20`, найдено прогоном 2026-08-05).

### `bin/sshlg-skills.js` — команда `config`

| Вызов | Вывод | Код |
|---|---|---|
| `config` | восемь строк `routers.<имя>  on\|off`, в порядке реестра | 0 |
| `config set routers.<имя> on\|off` | `routers.<имя>: <было> → <стало>` + напоминание про `routers --update` | 0 |
| `config set routers.<имя> <мусор>` | `состояние должно быть on или off` | 2 |
| `config set routers.<неизвестное>` | ошибка + список валидных имён | 2 |
| `config set <не-routers.*>` | ошибка + единственный поддерживаемый префикс | 2 |

Установка того же значения печатает `routers.<имя>: off (без изменений)` и
выходит 0 — идемпотентность видна оператору, а не только тестам.

### `test/run.js` (новый) и `npm test`

`npm test` = `node test/run.js`. Раннер:

1. гоняет `python3 test/validate.py`;
2. **находит** `test/*_test.js` через `readdir` и гоняет каждый;
3. падает с ненулевым кодом, если упал любой.

Обнаружение вместо списка — потому что список пришлось бы держать в
`package.json` и в CI одновременно, а это ровно тот класс расхождения, который
эта спека и закрывает. `check_pins.py` в раннер не входит: он ходит в сеть, а
`validate.py` обязан работать офлайн (решение 2026-08-05).

### `test/validate.py` — две новые проверки

1. `package.json` содержит `scripts.test`.
2. `.github/workflows/validate.yml` вызывает `npm test` — иначе локальный вход
   и CI разъезжаются молча.

## Тексты роутеров

Восемь. Каждый несёт четыре части, которые проверяет `router_texts_test.js`:
правило (`установлен` — для правил без участника читается как «правило
установлено»), граница в обе стороны (`**Граница` + `НЕ через`), фраза отказа
(`Фраза отказа`), место среди роутеров (`Место среди роутеров`).

**Место среди роутеров переписывается во всех восьми.** Существующая
формулировка перечисляет три роутера; при восьми она становится ложной. Новая
называет только **ближайших соседей по оси**, а полный порядок несёт таблица —
у неё для этого есть механика, у прозы нет.

## Область

Не входит: делегирование `routers --member` в инсталлерах четырёх участников
(C-07), per-project правила (ими владеет `/ux-rule`, спека 2026-08-05),
глобальные тумблеры на стадии пайплайна (ими владеет `pipeline.json` в
проекте).
