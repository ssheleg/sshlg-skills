# Spec: `npx sshlg-skills enroll` (2026-10-19, plan wave 5, REQ R10)

## Why

"A project is set up" has no definition and no command today. Each member seeds its own
layer through an interactive command (`/ux-init`, `/brand-init`, `/task-pipeline setup`),
`.claude/routers.json` is written by hand and is present in no repository on the
operator's machine, and nothing tells an agent opening a project which family routes
apply to it. The global routing block says what each router owns in general; it cannot
say "this repository has a public website, so seo-llmo and copywriting apply here, and
its brand pack is still missing".

## Contract

`npx sshlg-skills enroll [--root DIR] [--dry-run] [--json] [--surface public-web|app-text|internal]`
`npx sshlg-skills enroll --prune [--apply] [--root DIR] [--json]` (B-229, 2026-10-27)

1. **Detect** (pure, `lib/enroll.js`, handed a reader, never touching the filesystem
   itself, like `materialised.js`): the surface class and the signals behind it.
   - `public-web`: a web framework in `package.json` dependencies (next, astro, nuxt,
     @remix-run/*, @sveltejs/kit, gatsby, vite with an `index.html`, @11ty/eleventy),
     a Hugo/Jekyll config, `public/index.html`, `robots.txt` or a sitemap in the tree.
   - `app-text`: store metadata (`fastlane/metadata`, `store/`), a Telegram bot or Mini
     App dependency (telegraf, grammy, aiogram, python-telegram-bot, @telegram-apps/*),
     a mobile project (`ios/`, `android/`, `*.xcodeproj`, `pubspec.yaml`), user-facing
     string catalogues.
   - `internal`: none of the above.
   - Extra routes by signal: three or @react-three/* → `web3d-dev`; Telegram deps →
     `telegram-dev`; stripe, ad pixels, sentry, google sign-in → `sheleg-dev`; a
     WebXR/OpenXR/Meta SDK → `xr-dev`.
   `--surface` overrides the class, and the override is printed as an override.
2. **Plan the routes**: the routers that apply to the class, from `lib/routers-registry.js`
   (never a second list): `public-web` → task-pipeline, super-ux, copywriting,
   sheleg-design, seo-llmo, evidence-docs; `app-text` → task-pipeline, super-ux,
   copywriting, sheleg-design, evidence-docs; `internal` → task-pipeline, evidence-docs.
   Each route carries its setup state, read from the tree: brand pack
   (`docs/brand/voice.md`, `terminology.md`, `facts.md`), scenarios (`docs/ux/scenarios.md`),
   DOCMAP (`docs/DOCMAP.md`), SEO brief or audit (`docs/seo/brief-*.md`,
   `docs/seo/audit-*.md`), and the exact command that seeds what is missing
   (`/brand-init`, `/ux-init`, `/task-pipeline setup`, `/seo-aeo-audit brief` or audit).
3. **Write these things, and nothing else** (two until 2026-10-27; the third is B-229's):
   - one managed block `SSHLG:PROJECT` (managed-blocks/1 fence) listing the applicable
     routes, the surface and its signals, and the remaining setup commands. Written into
     the project's `CLAUDE.md` and `AGENTS.md` where each exists; when neither exists,
     `CLAUDE.md` is created holding only the block. The block is registered in
     `lib/blocks.js` `REGISTRY` as dedicated, writer `npx sshlg-skills enroll`, and the
     managed-blocks page gains its row.
   - `.claude/routers.json` entries **only for routers whose material already exists**
     (a voice pack, a scenarios file with its linter, a DOCMAP), so `materialised`
     reports them true. Existing entries and keys are preserved; enroll never removes or
     rewrites an entry it did not add, and never declares a file that does not exist.
   - `.claude/sshlg-enroll.json` (`{"schema": "sshlg-enroll-authorship/1", "about", "wrote":
     {router: entry}}`): the routers.json entries enroll added, as written. It cannot be a
     key inside routers.json: `materialised` reads every top-level key as a router and
     reports an unknown one false. Each run keeps a recorded entry only while routers.json
     still holds it unchanged (an edited or removed entry is the operator's from then on)
     and adds the entries this run wrote. It is created only when there is something to
     record. A malformed or symlinked record is refused like routers.json.
4. **Safety**: every byte outside the block is preserved; markers are parsed with
   `lib/blocks.js` (fence-aware); a malformed file, an operator `SSHLG:PROJECT:OPTOUT`,
   a symlinked instruction file or a root outside a Git work tree is refused with its
   reason. The file is copied through `apply.protect()` before the write. `--dry-run`
   writes nothing and prints the full diff, removals included.
5. **Idempotent**: a second and third run over the same tree write nothing and print
   `unchanged`; proven by running the real command three times on a fixture repository
   and comparing hashes (CLAUDE.md invariant 2).
6. **Exit codes**: 0 written, previewed or unchanged; 1 refused (with reason); 2 usage.
7. **`--prune`** (B-229, decided 2026-10-27): when material is deleted, the entry stays and
   `materialised` reports it false, the intended signal. `--prune` removes an entry only
   when all three hold: the record names it, routers.json holds exactly the recorded
   bytes, and a file it declares (`materialised` or `guards`) does not exist. An entry
   the record does not name (operator-written, or written before the record existed) is
   never removed; an edited one is kept and reported. No record removes nothing. The
   other entries keep their bytes and order, and the record drops what was removed. It
   previews with the full diff unless `--apply`; `--apply` writes through `apply.protect()`
   and the atomic writer, and a repeat prints `enroll --prune: unchanged`. `--apply`
   without `--prune`, `--prune --surface` and `--prune --apply --dry-run` are usage errors.

## Not in scope

Running `/brand-init`, `/ux-init` or the audit (they need a person's answers and a model);
writing any doctrine into the project; touching the global routing block.

## Tests

Pure detection fixtures per class and per extra route; the plan names only registry
routers (a fixture plants an unknown router and expects a refusal); block round trip with
foreign text above and below preserved byte for byte; opt-out honoured; malformed file
refused; routers.json merge keeps a foreign key and its order; no declaration for a
missing file (planted); three-run hash idempotence through the real CLI on a temporary
Git repository; `--dry-run` writes nothing (directory listing and hashes unchanged).
B-229: the record holds exactly the entries enroll added and none it did not; a re-run is
unchanged; an edited or removed entry leaves the record; a malformed or symlinked record
is refused; `--prune` removes a recorded entry whose material is gone and keeps an
operator-written one with missing material, an edited one, and every foreign byte; no
record removes nothing; the real command previews without writing, then `--apply` three
times leaves one hash with a backup of the pre-prune routers.json.
