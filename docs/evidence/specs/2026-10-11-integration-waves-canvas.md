# Canvas — the family working with Fabric, Observatory and every coding agent, at the lowest context cost

Spec for the `/task-pipeline waves` run of 2026-10-11 (lease `WAVES-1011`). It lays
the target state over the current system, node by node. The
[inventory](2026-10-11-integration-waves-inventory.json) puts every open item on a
node. It is generated by [the assign script](2026-10-11-integration-waves-assign.py)
from [the wave-0 survey](2026-10-11-integration-waves-raw/). The
[brief](../briefs/2026-10-11-integration-waves.md) owns the REQ table. The
[plan](../plans/2026-10-11-integration-waves.md) owns the waves and the task packets.

**Operator's goal (2026-10-11, verbatim intent):** close everything left undone or
done with errors, in waves, until an independent verifier confirms the system matches
the goal. The emphasis is optimization, and the skills working well together with
Fabric, Observatory and every available coding agent.

**The rule this canvas exists for:** no wave builds a shape that a later wave undoes.
Items that change one seam are designed together here, before any wave is cut.

## N01 — context budget

**As-is.** `hooks/user-prompt-submit.js` prints the routing note on every prompt that
matches a route (`lib/triggers.js:1078`), even when it printed the same routes on the
previous turn. `hooks/session-start.js` prints the pointer, the injectors line, and
any update, handoff or drift lines on every start, resume, clear and compact. The
family's 39 descriptions total 33,882 chars, and 14 of them sit within 60 chars of
the 970 cap.

**To-be.**
- **Once per route per session.** The prompt note names a route only the first time
  that route triggers in a session. `turnstate` records `noted: [route…]`. A SessionStart
  with `source` = `clear` or `compact` empties the record, because the context that
  held the earlier note is gone. Turns that bring no new route print nothing.
- **Injectors line only on change.** The SessionStart injectors line prints only when
  the set of injecting plugins differs from the set recorded in
  `state.json.injectors`. Drift, update and handoff notices keep their channel; each is
  already silent when there is nothing to say.
- **Description share as a ratchet.** The family's total description chars become a
  measured, ratcheted number in `test/validate.py`: it may fall and may not rise. Each
  member trimmed in this release lowers it.

**Contract.** The hook stdout formats are unchanged; only *when* a line prints changes.
`turnstate` gains one field. `state.json` gains one key (see N02).

## N02 — hook and credential integrity

**As-is.** `update` refreshes the runtime copy but never re-applies the
`settings.json` wiring (`bin/sshlg-skills.js:572-595`). When `WIRED` changed in 1.55.1,
the new MCP-credential matcher never reached this machine, and those DigitalOcean
calls are unguarded here. The secret remedies hardcode
`~/DATA/project-observatory/tools/use_secret.py` (`lib/secrets.js:109`), a checkout
path without `--vault-only`. Fabric Dashboards runs `npx sshlg-skills update` in the
background and reads `~/.sshlg-skills/state.json`. That consumer is undocumented, and
`update` has no single-instance lock.

**To-be.**
- **`update` re-wires a consented machine.** Where the family's hooks are already
  installed, `update` computes `hooks.plan()`. If only the family's own entries differ,
  it writes them through `protect()` (a backup first), exactly as `hooks install` does.
  A machine without hooks is still not asked. `hooks` status names the differing field
  (`matcher`, `command`, `order`).
- **Remedies resolve the engine at runtime.** Every secret remedy prints
  `"$(project-observatory full-path)/tools/use_secret.py" run --vault-only …`. The text
  lives in one constant, and a test refuses a checkout path.
- **`state.json` is a published interface.** `docs/` documents its keys (`updateCheck`,
  `inbound`, `injectors`) with a `schemaVersion`. `update` takes
  `~/.sshlg-skills/update.lock` (pid + start time; stale after 30 min) and a second
  concurrent run refuses, naming the holder.

## N03 — continuity layering (task-pipeline ↔ Observatory ↔ Fabric)

**As-is.** There are four handoff mechanisms and no map between them: the Git
`docs/HANDOFF.md` with the repository-handoff rule, the hub's inbound queue
(`lib/handoff.js`), Observatory's `memory.handoff` lease, and Fabric's
`session-handoff/1`. task-pipeline writes the Observatory checkpoint
(`continuity.md:319-331`), but adoption is 1 in 293 sessions. It never calls
`handoff_create`/`handoff_accept`. It does not read Fabric's `brief.md`/`task.md`,
does not read `docs/backlog-sources.json` (20 repos declare it), and names its packet
`execution-packet/1`, the name Fabric gave up. Release approval mode lives only in
the operator's CLAUDE.md.

**To-be — one layering, each layer one job:**

| Layer | Owner | Carries | When |
|---|---|---|---|
| Durable record | the repository (`docs/HANDOFF.md`) | objective, decisions, next task | every handoff, always |
| Workflow write-lease | Observatory `memory.handoff_*` | who may write the run now | a planned executor change |
| Stage checkpoint | Observatory `memory.checkpoint_*` | the gate just passed | every gate, when the tools are connected |
| Launch context | Fabric `session-handoff/1` | `brief.md`, `task.md` | a Fabric-launched session; intake reads them as the brief |
| Inbound queue | hub `lib/handoff.js` | PRs other agents left | session start |

- **Every gate writes the checkpoint** when Observatory's tools are connected. The
  ledger records the receipt id, or the line `memory: unavailable — <reason>`. A gate
  never fails because memory is unavailable.
- **A planned change of executor** issues `handoff_create`, and the successor's
  `handoff_accept` precedes its first write. `LeaseLost` remains only for unplanned races.
- **Intake reads the declared sources.** With `docs/backlog-sources.json` present, the
  waves intake reads exactly those sources. A Fabric launch's `task.md` seeds the brief.
- **The packet id is namespaced:** `task-pipeline/execution-packet/1`. Readers accept
  the old bare id for one release, then refuse it; the removal is wave 2 of the next
  release, named here.
- **The Fabric adapter contract is a fixture.** `fabric-pipeline-contract.json`
  (gate types and the `must_understand` set) runs in task-pipeline CI without a Fabric
  checkout. A NOT_RUN regression becomes a run.
- **The release stage reads the project's approval mode:** `checks` (release-guard, no
  reviewers) or `reviewers`. On `reviewers` it reports the waiting run's link. The
  operator file stops being the only home of that rule.

The map's single home is `docs/working-rules/handoff-layers.md` in the hub. task-pipeline
`continuity.md` and the routing block cite it and do not restate it.

## N04 — coordination (agent-sync ↔ Fabric coordination.md ↔ Observatory)

**As-is.**
- The run id is the first 12 alphanumeric chars of the session key
  (`agent_sync.py:630,654`), so similar ids share one lease.
- Expired lease files are never reaped (AS-11: 126 expired).
- A lease held for hours stalls Observatory's tick.
- The Notion token is read from plaintext `.env.agent-sync` (`:496-517`); 15 such files
  exist under `~/DATA`.
- No conformance to Fabric's `coordination.md` is declared.
- AS-07, AS-08, AS-09, AS-10 and AS-14 are open.

**To-be.**
- **Run identity:** `r-` + the first 12 chars of a sha256 of the full key. A fixture
  reproduces Observatory's collision.
- **Residue:** `status` counts expired leases; `reap --expired` removes only lock files
  whose owner run is provably finished (expired TTL + no live pid + not this host's
  live session). Each removal is journaled.
- **Long leases:** `status` and the PreToolUse hook warn when a lease outlives the
  repository's declared `scheduled_interval`. The doctrine says to release between
  batches.
- **Token:** resolution order is the Observatory vault slot (`use_secret.py run
  --vault-only`), then the environment, then `.env.agent-sync`. The last is reported
  as `degraded: plaintext token file`. Moving the values is the operator's step.
- **Conformance:** `references/fabric-coordination.md` maps each `coordination.md`
  operation to its command, pinned to a contract commit, and a test checks the map.
- **AS-07, AS-08, AS-09, AS-10, AS-14:** fixed, each with a fixture watched failing.

## N05 — delegation and interop doctrine (agent-stack, make-skill)

**As-is.** `gateway.md` teaches on-behalf-of tokens with no trust tiers. The operator
decided the tiers on 2026-10-11: fabric-workspace `knowledge/authority.md:63`, main
`eb451cf`. agent-interop does not teach `fabric-interop/0.1` jobs or the `degraded`
envelope. The Fabric adapter skills point at agent-stack and make-skill; nothing
points back. Every agent-stack description has 4–8 chars spare.

**To-be.**
- **Trust tiers in `gateway.md`:**
  - T0, the operator's own machine: no token, approval or grant record; the operator's
    instruction is the authority.
  - T1, the operator's enrolled machines: the same as T0.
  - T2, another person's machine or an outside caller: the full on-behalf-of model.
  - Money limits and human gates hold on every tier.
  - Cited to fabric-workspace `eb451cf`. The Fabric commit `19ad05ca` is named only as
    "Fabric ADR-0144 amendment 4, wave 2 branch" until it reaches Fabric main.
- **The fabric-interop job extension** (`fabric.job.get/cancel`; working /
  input_required / completed / failed / cancelled) and the
  `degraded`/`human_steps`/`sources` envelope become a worked example beside MCP Tasks,
  pinned to a contract commit.
- **Back-links:** agent-stack and make-skill name `fabric-agent-adapter`'s three skills
  and `observatory-log:handling-secrets` as the HOW for Fabric-compatible agents and
  credentials.
- **Descriptions:** each has at least 30 chars spare.

## N06 — task-pipeline hygiene, and the family's test-residue seam

**As-is.** Three temp-tree leaks: `test/validate.py:3459`,
`test/stage_checkpoint_test.py:55,199`, and `residue.workspace()` keeping trees on
failure. There are 41 bare `mkdtemp()` calls. make-skill MS-05 and agent-stack AG-06a
are the same seam in their repos. CI is at the 512 KB workflow ceiling and runs about
105 min. The description is at 909/970 and the body at 4749/4750 tokens.
`verification.md` still says "release pending" for a shipped release, and two
merged branches are still on the remote.

**To-be — one residue rule across the family:**
- Every test temp tree is made through the member's residue ledger.
- A guard fails on a bare `mkdtemp`/`TemporaryDirectory` outside the ledger.
- The ledger removes on success and keeps on failure, under a run-scoped parent dir
  named for the suite.
- Kept trees are reaped after 24 h by the next run of the same suite, and only its own.
- The existing leak is reaped once by the same rule; nothing outside a suite's own
  prefix is touched.

**CI.** Negative self-tests move from one step each into a data-driven runner (one step
reading a manifest), so `validate.yml` falls below 400 KB. The suite is sharded into a
matrix. Target: the validate job ≤ 45 min (measured on the PR that ships it).

**Budget.** The description ≤ 900 chars, and the body ≥ 100 tokens under the limit
(B-120: the move to references is named per section). The hub ratchet returns to 13.

**Ledgers.** `verification.md` gets a current header, the stale branches are deleted,
and HANDOFF is current.
