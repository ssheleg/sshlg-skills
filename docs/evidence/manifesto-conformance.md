# Manifesto conformance — the program backlog

> **What this is.** The single home for the **state of one cross-repository program**: bringing the
> ssheleg family into conformance with the Proof of Done manifesto
> (`~/DATA/pod-manifesto/manifesto.md`), after the 2026-08-18 audit that scored all nine members
> against 61 extracted requirements.
>
> **What this is NOT.** It is not a second copy of any member's debt. A row here that belongs to a
> member is *also* filed in that member's own `docs/evidence/backlog.md`, and **that file stays the
> single home for the member's debt**; this file is the single home for *program* state — which task,
> which agent, which wave, what closed it. Cross-referenced by id. Two homes for one fact is the
> defect M-44 names; two homes for two different facts is a propagation matrix.
>
> **Write discipline.** Only the orchestrating session writes this file. Task agents return a typed
> verdict and never edit it. That is deliberate: the audit's G4 found that no member implements the
> checker the manifesto requires before a convergence (M-25), and the family's lease is per-task-id
> rather than per-file (agent-sync audit, M-24), so 30 agents appending to one ledger is the exact
> collision the audit flagged. The orchestrator is the checker.
>
> **Source of every row.** `scratchpad/REPORT.md` (consolidated) and `scratchpad/audit-<member>.md`
> (nine per-member reports, each with `path:line` evidence). Audit date 2026-08-18.

## How to read a row

| column | meaning |
|---|---|
| `id` | program id. Prefix = owning repository. |
| `M` | the manifesto requirement it closes (M-01…M-61 from the extracted set) |
| `evidence` | where the defect was measured, `path:line`, relative to the owning repo |
| `done when` | the acceptance criterion — a command, a refused plant, or a resolved reference |
| `wave` | execution order. Rows in one repo never run concurrently; different repos do. |
| `state` | `open` · `claimed` · `landed` · `verified` · `deferred` · `dropped` |

`landed` means the change is committed. `verified` means an independent check observed it —
these are different states and the program does not collapse them (M-10).

## Field notes — things the program learned about itself

**2026-08-19, the rescue.** A close was one `git checkout main` away from being garbage. See UM-08.
The lesson is not "check your branch": it is that the family's convergence guard is written to
disclose what it cannot see, and this program produced a case where the undisclosed state was the
dangerous one. A disclosure is the correct floor, not the ceiling.

**2026-08-19, a plant that did not land.** Verifying SU-01, my first planted defect used a `sed`
range form that silently matched nothing. The linter exited 0 and I nearly recorded a guard as
not firing. `make-skill`'s `plant_guard.py` exists for exactly this — it refuses when the plant
did not land, rather than approving — and the lesson generalises past that repo: **a negative
control needs its own positive control.**

**2026-08-19, a plant that went red for the wrong reason.** Verifying SG-02, my plant tripped the
kit-drift check twice before reaching the reduced-motion check. Without asserting the *message*,
that plant would have reported "caught" while the new check never ran. SG-02's author had already
added an `expect` field for this; my independent plant reproduced the need for it.

**2026-08-19, my own script passed for the wrong reason.** The first attempt to insert ALL-49 into
this file was guarded by `if "ALL-49" not in t`, which was satisfied by a *reference* to ALL-49
inside another row's note, so the row never landed and the script reported success. Fixed with an
anchored assertion. Recorded because it is the same defect class the program exists to close,
committed by the orchestrator, in the ledger that tracks it.

**2026-08-19, a member solved the umbrella's own bug.** `SD-03` shipped a `PreToolUse` gate that
correctly separates a command from a quotation: a reader grepping for `sk_live_` is allowed, a
heredoc fed to `cat` is data, the same heredoc fed to `bash` is a script, whole-line comments are
dropped, and a non-Bash tool is judged on its name and never its input — *because that is where
documents arrive*. I verified all six by running the hook as a process. The umbrella's `repo-gate`
fails exactly this distinction (`UM-10`) while the umbrella already owns the solution in
`lib/hygiene.js`. So the fix for UM-10 is not new work; it is reuse, and a member has now proved
the shape twice over.

**A boundary held that mattered more than the row.** SD-03's gate is live automatically on the
plugin channel, and absent on the copy channels — `install.sh` and `npx skills add` copy only the
six skill directories. The honest fix would be to write a `PreToolUse` entry into the operator's
own settings file. It did not do that, and said why: writing to a file the operator owns and did
not write is the one thing this family must not do unasked. It printed a reminder instead, filed
`B-90`, and recorded in its own report that **a printed reminder is a warning, which M-30 calls
weaker than a precondition.** That is a refusal to close a row by overreaching, stated as a
limitation rather than hidden as a success.
