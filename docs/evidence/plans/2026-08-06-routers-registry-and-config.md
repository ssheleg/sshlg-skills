# План — реестр роутеров и настройки пака

Спека: `specs/2026-08-06-routers-registry-and-config-design.md`

**Параллельных групп нет.** Восемь задач сходятся на четырёх файлах
(`routers.js`, `migrate.js`, `bin/sshlg-skills.js`, `validate.py`), причём
T3 и T4 правят один файл по разным причинам. Развести по владению не выходит —
значит последовательно, а не «параллельно и потом мержить».

Каждая задача: красный тест → минимальная реализация → зелёный → коммит.

| # | Задача | Файлы | DoD |
|---|---|---|---|
| T1 | Примитивы файла состояния | `lib/store.js` (нов.), `lib/consent.js` | `node test/consent_test.js` проходит **без единой правки теста**; новый `store_test.js` доказывает режим 0600 на существующем файле |
| T2 | Конфиг | `lib/config.js` (нов.), `test/config_test.js` (нов.) | дефолт `on` без файла; битый JSON → дефолты; `set` пишет; stash кладёт/отдаёт/чистит; режим 0600 |
| T3 | Реестр восьми | `lib/routers-registry.js` (нов.), `lib/routers.js`, `lib/router-texts.js`, `test/router_texts_test.js`, `test/registry_test.js` (нов.) | 8 текстов × 4 части; `resolve` уважает `requires` и конфиг; `rows` в порядке реестра; фасад `forMembers` работает по-старому |
| T4 | Удаление секции | `lib/routers.js`, `test/routers_test.js` | `remove` убирает секцию и ровно один разделитель `'\n'`/`'\n\n'`; chrome с текстом цел; строка уходит из таблицы; повторный `remove` — no-op; проза вне блока побайтово цела |
| T5 | Вытесненные заголовки | `lib/migrate.js`, `test/migrate_test.js` | `## Task planning` уходит **только** когда пишется `task-pipeline`; тело в stash; без роутера — файл не тронут |
| T6 | Команда `config` + проводка | `bin/sshlg-skills.js`, `test/cli_config_test.js` (нов.) | пять строк таблицы вывода из спеки, точный текст и код выхода; `routers` резолвит через реестр+конфиг и передаёт `remove` |
| T7 | `npm test` и защита от расхождения | `test/run.js` (нов.), `package.json`, `test/validate.py`, `.github/workflows/validate.yml` | `npm test` exit 0; раннер **находит** наборы; validate.py падает, если нет `scripts.test` или CI не зовёт `npm test` |
| T8 | Доки | `README.md`, `CHANGELOG.md`, `docs/DOCMAP.md` (нов.) | каждое число вычислено, каждая команда разрешима |

## Проверка каждой новой проверки

R-11 требует не «тест написан», а «тест **увиден падающим**». После T7 каждая
новая фикстура получает подсаженный дефект и должна упасть; результат печатается
в приёмке. Зелёный от проверки, которую никто не видел красной, — не
доказательство (`references/gates.md`).
