# Routing measured, 2026-09-14 — the phrases nobody had probed

Five descriptions changed since the family's last eval run (2026-08-31) and none of the
five changes had been measured. One of them was made **in this session**: `stripe-billing`
advertised bare `биллинг`, which collided with `agent-orchestrator`'s `биллинг LLM` across
packs where no per-repo validator can see it, and was narrowed to `биллинг подписок`.
Changing a routed phrase without measuring it is the defect the family's own eval doctrine
exists to prevent, so it was measured before the release that carried it.

## Method

Same shape as `agent-sync`'s 2026-08-31 run, which is the family's reference.

- **Corpus.** One file, 28 skills, one `- name: description` line each, built from the
  SKILL.md front matter of every family plugin **as it stands today** — not from an
  installed roster, and not from memory. 23,907 bytes.
- **Probes.** One fresh, context-free `general-purpose` subagent per query per model
  through the Claude Code Agent tool. Each is told to `cat` the corpus, that the file is
  the authoritative and complete skill list, to ignore any other listing, and to answer in
  two lines: the number of skills in the file (proving the read), then one skill name or
  `none`. **Ten probes: five queries × two models**, no retries, first answer recorded.
- **Models.** `haiku` and `sonnet` through the Agent tool's aliases.

## Results — 10/10

| Query (the changed phrase in it) | Expected | haiku | sonnet |
|---|---|---|---|
| «Нужно настроить **биллинг подписок** … списывалось ежемесячно» | stripe-billing | pass | pass |
| «Перепродаём доступ к LLM … **биллинг LLM** … по тенантам … с наценкой» | agent-orchestrator | pass | pass |
| «Сделай **редизайн** главной страницы» | sheleg-design | pass | pass |
| «Перепиши **текст ошибки** … звучит грубо» | copywriting | pass | pass |
| «Проведи **аудит скилов** … соответствуют ли стандарту» | make-skill | pass | pass |

Every probe reported reading 28 skills. The two billing queries are the pair that
mattered: before this session both would have matched `stripe-billing`'s bare `биллинг`,
and the narrowing is what separates them. It is measured in both directions rather than
assumed — the LLM-metering query reaches `agent-orchestrator`, the card query reaches
`stripe-billing`, on both models.

## What this does not measure

Five queries, one sample each. A contested cell in the reference run is sampled n=3; none
of these was contested, so none was resampled — and a single pass is weaker evidence than
three. It measures **trigger routing from descriptions**, not whether the skill then does
the job: no scenario was driven end to end here. The corpus is the family's 28 skills
alone, so it says nothing about the ~400 other skills a real session on this machine can
reach, where a near-miss neighbour could take a query this corpus never offers it.
