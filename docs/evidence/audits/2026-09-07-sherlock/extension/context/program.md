# Программа доведения ssheleg skills

Цель: получить проверяемое семейство skills, где улучшение instructions повышает качество работы, контекст сохраняется между исполнителями, а установка воспроизводится на явно поддержанных hosts. Исходный аудит охватывает 28 skills / 9 packs; extension добавляет углублённые проверки task-pipeline/Fabric, design и updates. [Исходные измерения](../../report-validation.json), [новые находки](../findings-final.json).

Архитектура: request → typed routing → research/grill только неизвестного → spec → module/interface decisions → graph + immutable packets → capability/freshness/claim gate → isolated executors → independent review → integration → host/release evidence. Исследование и план может выполнить один агент. Исполнители стартуют из пакета и читают closure, не историю планировщика. Fabric — один возможный execution authority.

Порядок программы: (0) удержать опасные операции обновления и исправить доказанные money/auth/claim дефекты; (1) закрепить contracts и прямые UX/design рекомендации; (2) реализовать packet compiler, execution authority и graph proof semantics; (3) внедрить Fabric adapter и host-aware delivery; (4) закрыть оставшиеся factual/eval/kit defects; (5) пройти реальное cross-host/cross-model outcome сравнение и staged release. Независимые ветки идут параллельно, dependencies и write scope ограничивают dispatch. Номер волны — расчётная последовательность при неограниченном числе работников, не календарное обещание.

100% означает: все 115 findings закрыты связанными tests/commits/release receipts; четыре enabling задачи приняты; каждый из 28 skills имеет outcome cases; explicit support matrix проходит загрузку и smoke на выбранных версиях hosts; unsupported явно исключены; install/update/rollback verified; реальный planner→другой executor→reviewer→integrator handoff работает; visual evaluation использует рендеры, а не prose. Результат LLM нельзя гарантировать для любого будущего запроса. Настоящий release gate ограничен версионированным корпусом и измеренными capabilities.

Главные неразрешённые продуктовые решения: какие host/version tiers официально поддерживаем; инфраструктурный backend Fabric authority; budget/model matrix реального eval. Предложение: обязательный tier Claude Code + Codex, остальные 12 объявленных adapters остаются отдельно gated до smoke receipts. Это не разрешение молча выбросить их из поддержки. Зависимые capability checks блокируются до фиксации matrix; локальные correctness fixes этого решения не ждут.

Разделение областей: текущий отчёт и локальные doctrinal patches выполнены; runtime, merge, release, install updates не выполнены. Nicegram используется как read-only пример кликабельного flow. Source files в packets закреплены hash на момент аудита; после любого изменения требуется новая revision и повторная проверка closure. Program/module docs — предлагаемые решения, факты о дефектах имеют собственные locators в каждом packet.
