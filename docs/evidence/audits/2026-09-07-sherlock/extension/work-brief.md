# Дополнение аудита — brief и границы исполнения

Источник полномочий: запрос пользователя в этой задаче от 2026-09-07. Модель наследуется из текущей задачи. Повторное интервью не требуется: цель, порядок и форма результата заданы; найденные несовместимости фиксируются как решения или явно ограниченные предложения.

| REQ | Результат | Проверка |
|---|---|---|
| E-01 | Проверить разделение task-pipeline на планировщика и независимых исполнителей | Текущий graph CLI, сохранённый контекст, отдельные процессы, границы прав и интеграция результатов |
| E-02 | Проверить возможность использования как pipeline Fabric | Сопоставление реальных API/schema/code Fabric с контрактами task-pipeline; обозначить недостающий adapter |
| E-03 | Углубить диагностику визуального качества | Трасса правил и конфликтов; подтверждённые свойства отдельно от причинных гипотез |
| E-04 | Зафиксировать интерактивный UX flow как рекомендацию скиллов | Изменения ux-flows/ux-scenarios, каноническая reference, согласование с build gate и shipped copies |
| E-05 | Финализировать старые 90 замечаний и новые выводы как приоритизированный backlog | Покрытие всех finding, типизированные зависимости, нет циклов/потерянных задач |
| E-06 | Дать каждой задаче полный связанный контекст | Program → module → contracts/decisions → task; source digest, implementation direction, DoD, rollback |
| E-07 | Проверить Claude Code, Codex и другие декларируемые среды | Матрица фактического discovery/install/routing/enforcement, неизвестное не называется поддержанным |
| E-08 | Проверить npm/plugin обновления | Offline fixtures, read-only registry checks, целостность/активный источник/ошибки/rollback |
| E-09 | Внести предметные рекомендации в сами skills | Изолированные worktrees, узкие doctrine/reference changes, релевантные validators и patch artifacts |
| E-10 | Проверить предлагаемый механизм передачи контекста | Executable packet validator и cold-start handoff simulation с негативными сценариями; не объявлять его production adapter |

## Решения по области

- Этот run расширяет аудит и готовность плана; не исполняет весь backlog и не делает production-интеграцию Fabric.
- Прямые изменения ограничены рекомендациями task-pipeline, UX и визуального процесса. Runtime features и fixes сохраняются как отдельные задачи с приёмкой.
- Fabric и Nicegram читаются как источники/референсы; активные проекты других задач не изменяются.
- Исходные checkout остаются базой аудита; правки делаются в отдельных worktrees ветки `codex/context-ready-skills-20260907`. Публикация npm, release и обновление всех установленных агентов в этот run не входят.
- Исходный аудит не переписывается: extension сохраняет новый срез и supersedes ссылки там, где появились дополнительные сведения.
- Контрольные/ресурсные зависимости не удаляются за отсутствие data payload; dependency type обязателен.
- Прототип flow проверяет модель переходов. Он не доказывает работающий backend, визуальное качество production или продуктовый эффект.

## Порядок

Harvest и scope → три независимых предметных аудита → doctrine changes → связанные context packets → dependency/ownership/freshness проверки → консолидированный отчёт и готовый backlog. Узкие checks изменённых пакетов выполняются после edits; полный 429-negative suite task-pipeline повторяется только при затронутом runtime/validator, а не ради новой reference.
