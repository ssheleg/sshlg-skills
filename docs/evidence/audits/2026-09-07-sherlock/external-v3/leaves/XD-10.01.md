# XD-10.01 — Связать stress matrix с существующим UX contract

Parent `XD-10` · implementation · P2

## Что и зачем

Связать stress matrix с существующим UX contract

Конкретная реализация приведена в шагах ниже.

## Решения

Согласовать с root UX recommendation; не писать параллельный flow schema.

Общие решения: использовать существующие family owners и artifact paths; не добавлять обязательные external packages/keys/runtime fetch. Parent acceptance и provenance сохраняются. Модель наследуется. Historical evidence read-only.

## Модуль и связи

Назначение: Vision → UX foundation → flows ↔ scenarios → prototype → UX audit; brand/copy.

Вход: цели, аудитория, ограничения и evidence с происхождением. Выход: scenario graph, flow coverage, UI strings и product decisions. Дизайн читает эти outputs, а не изобретает другое поведение.

Граница: Assumption, operator decision, implementation evidence и production effect не превращаются друг в друга автоматически.

Прежние сценарии мигрируются без выдуманного observed status.
Один visual polish не требует всех продуктовых состояний.
Interactive evidence соответствует тем же states/viewports, что visual compare.

Positive и исходный failure case проверяются по поведению, не по повторению слов инструкции.
